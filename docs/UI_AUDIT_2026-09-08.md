## The five things that would have gone wrong in the demo

1. Three money tables printed raw database ids where a creator name belongs.
2. Trackers labelled a sound nobody has measured yet "declining", in red.
3. A dropped connection told the user their campaign had been deleted.
4. Billing rendered the literal word `Infinity` in 24px bold on every paid plan.
5. Six `The width(-1) and height(-1) of chart should be greater than 0` warnings —
   the first paint of every Recharts container.

All five are fixed. The full list follows.

## 5. Charts

### P1 · engineering · every `ResponsiveContainer` logged a `-1 × -1` warning on first paint — FIXED
Recharts 3.8.0 initialises its measured size to `{-1, -1}` and only reads the real box in an
effect, so the guard at `component/ResponsiveContainer.js:135` fires on the first render of
any percentage-sized container regardless of the container's CSS. It passes if *either*
dimension is positive.

`ChartFrame` now owns the box — a floor the height never drops below, `minWidth: 0`, and
`initialDimension` seeded with that floor — and 15 call sites were migrated to it across
`CampaignTabCharts`, `PayoutTrendChart`, `MonthlySpendChart`, `AnalyticsCharts`,
`MarketplaceAnalytics`, `DashboardCharts`, `PerformanceTab` and `SharedPerformanceReport`.

Measured over nine dashboard routes in Chrome: **6 warnings before, 0 after.**
`campaigns/[id]/posts/[postId]/PostCharts.tsx` still uses a raw `ResponsiveContainer` — out
of scope for this pass.

### P1 · user · `SharedPerformanceReport.tsx:214` — the public report's pie can still collapse — OPEN
`useIsMobile` initialises to `false` and corrects in an effect, so the first client paint on
a phone lays out `1fr 1.4fr` in a 343px viewport. The `ChartFrame` migration means the chart
no longer warns, but the breakpoint should be CSS, not JS. The file's grid layout was left
alone: `SharedPostList.tsx` and the report's data path are out of scope.

### P2 · user · `CampaignTabCharts.tsx:100` — `<Cell fill="var(--cc-bg)" />` — OPEN

### P2 · user · `DashboardCharts.tsx:176` — `<YAxis type="category" width={104} />` — OPEN

## 6. Freshness — every number here is up to a day old and nothing said so

`vercel.json` runs all three crons daily: `sync-posts 0 2 * * *`,
`auto-approve-submissions 0 3 * * *`, `snapshot-sounds 0 4 * * *`.

### P1 · product · no "last updated" anywhere — PARTLY FIXED
A grep across `app/(dashboard)/dashboard/**` for `lastSyncedAt` / "last synced" / "as of"
returned zero hits before this pass. `LastUpdated` now runs on the trackers page: a page-level
"Last sync" line and a per-row chip that turns amber past 48 hours (two missed crons).
Verified in the browser — the chip resolves to `rgb(250,178,25)` on a 24-day-old snapshot.

**OPEN**, in order of exposure:
- `SharedPerformanceReport.tsx` — the **public client report** has no freshness field at all;
  its prop surface is `{ token, campaignTitle, data }` and `CampaignPerformance` carries no
  `asOf`. An agency client opens the link three weeks later, reads "1.2M views", and quotes
  it in a deck. Needs `dataAsOf` on the report type — an out-of-scope contract change.
- `campaigns/[id]/PerformanceTab.tsx` — six headline numbers, no as-of, no refresh; this is
  the tab behind the share link.
- `MarketplaceAnalytics.tsx:134` — accrued spend against a live cap, no timestamp.
- `creators/[id]/page.tsx:894` — the social card shows when the account was *linked*, never
  when its follower count was last true, though `updatedAt` is already on the wire.

### P1 · product · `lib/metric-definitions.ts:288-292` — "New today" is not today — OPEN
The value is `videosAdded24h` from the latest snapshot, written at 04:00. Read at 23:00 it is
~19 hours stale; if the cron failed it is yesterday's number presented as today's. Neither
"since this morning" nor "recorded today" is true. Same for `trackersTrending` ("climbing
right now") and `trackerUses`.

### P1 · product · `campaigns/[id]/posts/[postId]/page.tsx:403` — copy promises hourly, cron is daily — OPEN
"Tracking on — hourly snapshots for 72h build this post's time series." `lib/sync/cadence.ts`
does return an hourly cadence, but the only caller is `/api/cron/sync-posts`, scheduled
`0 2 * * *`. The promised 72 hourly snapshots arrive as 3 daily ones. Either the schedule or
the copy has to move; both files are out of scope.

### P0 · product · `settings/billing/page.tsx:90-92` — `Infinity` — FIXED

### P1 · product · billing promised usage tracking it did not show — FIXED

### P0 · product · `lib/reports/campaignPerformance.ts:82` — budget displayed as spend — OPEN
