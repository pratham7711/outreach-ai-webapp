## NEEDS DECISION (21 — no existing resource, or a product call)
- **New resources absent from rbac.ts:** `clients` (POST/PATCH), `lists` (5 routes), `messages` (2 routes), `trackers` (2 routes). Recommend adding `clients:*`/`lists:*`/`messages:manage`/`trackers:*` with role grants TBD.
- **AI routes** `ai/briefing`, `ai/nl-query`, `campaigns/[id]/outreach/draft`: gating on `analytics:read` excludes MEMBER entirely (MEMBER has no analytics grant). Decide if MEMBER should use AI. Consider `ai:use`.
- **`financial-reports/generate`**: exposes payout figures; ambiguous between `analytics:read` / `payments:read` / `reports:*`.
- **`fraud-flags/[id]` PATCH**: org-wide resolve, no campaign join → can't enforce `campaigns:edit_own`; currently UNGATED (see finding 2).
- **`negotiations/approve` + `reject`**: `payments:manage` is the closest fit but locks MANAGER out of closing deals on campaigns they run. Consider a `campaigns:approve_deals` permission.

## Security findings (independent of the sweep — current auth wrong/missing)
1. **`reports` POST + `reports/[id]` PATCH: ZERO RBAC check** (only feature-entitlement). VIEWER can create a report or flip `isPublic:true` to expose data. Sibling DELETE already guards `reports:*`. → **FIXED 2026-08-12.**
2. **`fraud-flags/[id]` PATCH: no RBAC, org-wide.** Any user can resolve/suppress any fraud flag. → gated conservatively to `campaigns:edit` (MANAGER+); proper campaign-scoping is a follow-up.
3. **`campaigns/[id]/negotiations/[offerId]` PATCH can set `ACCEPTED`** bypassing `negotiations/approve`'s finalRate+audit logic. Business-logic duplication — separate review.
4. **`creators:edit_own` is unenforceable** — `Creator` has no `createdById`, so MEMBER can edit any creator org-wide. Needs a schema field to honor the `_own` intent (or lock creator edit to MANAGER+).
